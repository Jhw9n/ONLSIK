# 자연어 식사 입력 UI

Figma `2213:894`(기본), `2213:533`(입력 중)의 레이아웃을 기준으로 구현했습니다.

## 현재 범위

- 기록 화면의 식사 추가 버튼에서 `MealEntryView`를 엽니다. 선택한 날짜와 식사 종류를 유지합니다.
- 입력창에 초점을 두거나 내용이 있으면 테두리와 초록 그림자를 표시합니다. 공백만 입력하면 전송할 수 없습니다.
- 입력창은 한 줄 높이로 시작해 줄바꿈에 따라 최대 6줄까지 늘어나며 이후에는 입력 영역 안에서 스크롤합니다.
- 하단 기록하기 버튼은 항상 표시하고, 추가 선택을 마쳐 유효한 확인 카드가 있을 때만 활성화합니다.
- 전송하면 키보드를 내리고 최근 식사 영역을 분석 중 → 추가 선택 또는 확인 카드로 교체합니다.
- 입력을 수정하면 기존 분석 및 결과를 무효화합니다. 이전 비동기 요청이 늦게 끝나도 새 결과를 덮어쓰지 않습니다.
- 최근 식사는 해당 사용자의 선택 날짜까지 최근 30일 기록을 날짜·식사 종류별로 묶어 중복을 제외한 3개를 표시합니다.
- 최근 식사를 선택하면 저장 전 분량을 확인하고 조정할 수 있습니다. 확인 버튼을 눌러야 해당 날짜·종류에 한 끼 전체를 저장합니다.
- 확인 카드 안에서 −/수량/＋로 양을 수정합니다. 줄·공기 등은 0.5씩, g·mL는 10씩 조절하고 가운데 숫자는 소수 둘째 자리까지 직접 입력할 수 있습니다. 입력 범위는 0.1~10,000이며 빈 값·잘못된 값일 때는 기록하기를 비활성화합니다.
- 최근 식사의 무게 표시는 저장된 분량을 환산한 것으로, AI가 새로 추정한 값이라고 표시하지 않습니다.
- 실제 AI 분석은 아직 연결하지 않았습니다. 앱에서는 연결 전 안내와 기존 음식 검색 경로를 제공합니다. 임의의 음식이나 영양값을 저장하지 않습니다.

## 프리뷰

`MealEntryPreview.swift`에서 기본, 활성, 분석 중, 추가 선택, 확인, 첫 기록, 연결 전 상태를 확인할 수 있습니다.
기본 프리뷰에서 `김밥 한 줄이랑 라면` 또는 `스파게티`를 전송하면 임시 분석 흐름을 확인할 수 있습니다.
프리뷰 영양값은 화면 확인용 예시입니다. 프리뷰는 저장 대신 입력 화면으로 돌아오며 실제 기록에 접근하지 않습니다.

## 다음 연결 지점

`MealEntryAnalyzing` 구현체를 `MealEntryViewModel`에 주입합니다. 현재 기본 구현체는 명시적으로 연결 전 오류를 반환합니다.
AI 연동 시 음식 식별·분량·영양값의 근거, 지원 여부, 응답 검증, 제한 시간, 질문 후 추가 분석이 필요한 흐름을 별도로 구현해야 합니다.
확인된 결과만 `MealEntryItem`으로 전달하고 불명확한 입력은 추가 선택 또는 재입력으로 안내합니다.
곁들임 음식은 자동으로 추가하지 않습니다.
