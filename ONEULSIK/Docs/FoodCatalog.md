## 포함 및 제외 기준

- 열량, 탄수화물, 단백질, 지방 4개 값이 모두 명시된 항목만 포함합니다. 나트륨·식이섬유 등 다른 영양소의 유무는 필터 조건이 아닙니다.
- 명시된 `0`은 유효한 값입니다. 빈칸, `-`, 미량 등 숫자로 확정할 수 없는 표기는 0으로 대체하지 않습니다.
- 기준량이 100g 또는 100mL인 항목만 사용합니다. 농촌진흥청 값은 가식부 100g 기준입니다.
- 100g/100mL당 열량 950kcal 초과, 개별 주요 영양소 100g 초과, 세 주요 영양소 합 105g 초과는 보수적인 품질 필터로 제외합니다. 이 필터는 모든 오류를 탐지하는 영양학적 검증을 대신하지 않으며, 고밀도 액체 등 일부 유효한 자료도 제외될 수 있습니다.
- 이름·업체·기준단위·4개 영양값이 같은 항목만 중복 제거합니다. 조리법·브랜드·영양값이 다른 음식은 유지합니다. 동일 항목에서는 표시 우선순위, 최신 기준일, 식품코드 순으로 선택합니다.
- 농촌진흥청 식품코드에는 `RDA-` 접두사를 붙여 식약처 코드와 구분합니다.

파일별 제외 건수·SHA-256·최종 수록 수·대표 음식 검색 건수는 `FoodCatalogImport.json`에 있습니다. 검색 건수는 상품/변형을 포함한 부분일치 수이며, 서로 다른 일반 음식 종류 수가 아닙니다.

## 앱 동작

- 음식명과 업체명으로 검색합니다. 공백으로 구분한 검색어는 모두 일치해야 하며, 대소문자·공백·문장부호를 정규화합니다. 계란/달걀, 자장/짜장, 흰쌀밥/쌀밥, 돈까스/돈가스 표기를 함께 찾습니다. 김밥·볶음밥·찌개·칼국수 복합명은 `참치김밥`과 `김밥 참치`처럼 순서가 다른 이름도 검색합니다.
- 일반 음식·원재료, 급식, 브랜드/가공식품 순으로 표시합니다. 각 그룹에서는 정확한 이름, 이름 접두사, 나머지 부분일치 순이며 같은 순위에서는 원재료를 우선합니다. 한 번에 최대 100건을 표시합니다.
- 브랜드·제품은 검색 시에도 정규화한 이름·업체·기준단위·4개 영양값이 모두 같은 결과만 합쳐 최신 기준일의 항목을 남깁니다. 돈까스/돈가스 통합은 기존 번들 DB에도 적용됩니다.
- 일반 음식과 브랜드·제품 음식을 구분해서 표시합니다. 일반 음식이 있으면 제품은 처음 5개만 표시하고 `더 보기`로 나머지 검색 결과를 펼칩니다. 제품만 검색되는 경우에는 접지 않습니다.
- 일반 음식은 정규화한 이름과 기준단위가 같으면 100g/100mL당 열량이 가장 낮은 항목 하나만 검색에 표시합니다. 열량이 같으면 기존 우선순위, 최신 기준일, 식품코드 순으로 선택합니다. 선택된 항목의 탄수화물·단백질·지방도 그대로 사용합니다. 추가 펼치기는 없으며 생것·삶은것 등 조리 상태와 브랜드·제품은 구분합니다. 이는 검색 표시 정책이며 원본 DB와 이미 저장한 식단 기록은 유지합니다.
- 원재료의 `생것` 접미사는 기본 식품명과 같은 검색 순위로 취급합니다. 예를 들어 사과 검색 시 `사과, 생것`이 사과차보다 먼저 표시됩니다.
- 입력 후 200ms 대기하며 검색은 별도 actor에서 수행합니다. 취소된 검색 결과는 UI에 반영하지 않습니다.
- 영양 DB는 **100g 또는 100mL 기준**을 그대로 유지합니다. 대표 분량이 연결된 일반 음식은 공기·그릇·줄·개·인분 단위로 선택하며, ± 버튼으로 반 분량씩 조절합니다.
- 모든 음식에서 g/mL 직접 입력을 지원합니다(0.1~10,000, 소수 둘째 자리까지). 입력 모드를 전환해도 실제 양은 유지하며, 빈값·음수·0·범위 밖 입력은 저장하지 않습니다. 대표 분량이 없으면 직접 입력이 기본입니다.
- 수량창은 원본 디자인의 간격을 사용하는 내용 높이 기반 하단 패널입니다. 대표 분량 안내는 음식명 아래에 표시하고, 직접 입력은 수량 버튼과 같은 위치에서 g/mL로 입력합니다. 키패드가 열리면 완료 버튼과 부가 영역을 숨기고 입력칸 아래로 키패드가 붙도록 패널을 올립니다. 내부 스크롤이나 키패드 닫기 버튼은 없으며, 음식명 또는 바깥 영역을 누르면 키패드가 닫혀 완료 버튼이 다시 나타납니다. X는 수량창을 닫고, 키패드가 닫힌 상태에서 바깥 영역을 눌러도 닫습니다.
- 대표 분량이 없는 음식은 iOS 26 이상에서 Apple Intelligence 모델이 사용 가능하면 음식명·분류·단위를 바탕으로 일상적인 분량을 추정합니다. 결과는 `AI 추정: 한 줄 기준 약 200~250g 정도예요`처럼 기존 안내 자리에 표시합니다. 별도 로딩 표시 없이 기존 안내를 유지하며, 미지원·생성 실패·추정 불가인 경우에도 기존 안내를 사용합니다. 생성된 분량은 참고 문구이며 입력값이나 영양 계산에는 반영하지 않습니다. 성공한 결과는 앱 실행 중 최대 200개까지 메모리에 보관하고 화면 종료 시 작업을 취소합니다.
- 원본의 제품 총중량이나 섭취참고량을 임의로 1인분으로 간주하지 않습니다. mL를 g으로 바꾸거나 밀도를 추정하지 않습니다. 공식 제품 제공량은 현 카탈로그에 검증된 값이 없어 아직 연결하지 않았습니다.
- 새 식단은 선택한 양에 비례한 영양값을 저장합니다. 기존 식단은 저장 당시 이름·제공량·영양값을 그대로 유지합니다. 추가된 부피 속성의 기본값은 0입니다.

## 대표 분량

`FoodPortion.swift`의 명시적 이름 목록에만 연결합니다. 브랜드가 없고 가공식품이 아니며 g 기준인 음식만 대상입니다. `밥`이나 `달걀`이 이름에 들어간다는 이유로 볶음밥·과자·난황·분말 등에 같은 양을 적용하지 않습니다. 이름이 같은 학교 급식 등 mL 기준 항목에도 g 분량을 적용하지 않습니다.

이는 해당 제품을 측정한 값이나 섭취 권장량이 아닌 **대표 음식의 참고 분량**입니다. UI에는 `약 ○○g · 대표 분량 기준`을 표시하며 출처는 아래 표와 분량 모델에 보존합니다. 검색 결과의 열량도 같은 대표 분량으로 표시합니다. 직접 입력은 실제 입력량으로 계산합니다.

### 대표 분량 추가 연결

- 위 외식 자료에서 삼계탕 1인분 1000g, 짬뽕 1그릇 1000g, 탕수육 1인분 200g, 해물칼국수 1그릇 900g, 생선초밥 1인분 300g, 군만두 1인분 250g, 물만두 1인분 120g을 추가했습니다.
- [식약처 외식 영양성분 자료집 제2권(2013)](https://www.foodsafetykorea.go.kr/upload/mkisna/2013.pdf)의 제공량을 추가했습니다. 각 음식의 PDF 페이지 번호는 `FoodPortion.additionalPortion`의 `sourceURL`에 포함합니다. 치즈김밥, 잔치국수, 수제비, 볶음밥·초밥 변형, 부대찌개, 설렁탕, 베이글 등의 명시적인 이름에만 연결합니다.
- 자료의 중간/큰 접시는 UI에서 `접시`, 면·죽의 1인분은 `그릇`으로 표현합니다. 케이크·전·초밥처럼 개별 크기가 불명확한 경우에는 제공량 그대로 `인분`을 사용합니다. 만주 2개 70g → 1개 35g, 동태전 6개 150g → 1개 25g 등 명시된 개수만 나누어 사용합니다. 치즈김밥 250g은 한 줄 참고량으로 표시합니다.
- 현재 번들에서는 89개 음식명, 102개 항목에 대표 분량이 연결됩니다. 이는 표기 변형을 포함한 이름 수이며 브랜드 상품의 분량까지 확보했다는 의미는 아닙니다. `김밥 참치`, `김밥 치즈` 같은 DB 표기도 포함합니다. 돈가스김밥처럼 근거 분량을 확인하지 못한 음식은 g 입력과 AI 추정 안내를 유지합니다.

## 재생성

Python 3.11 이상 및 `openpyxl`이 필요합니다. 공식 사이트에서 위 버전의 Excel 파일을 내려받은 뒤 프로젝트 루트에서 실행합니다.

```sh
python3 Scripts/build_food_catalog.py \
  --mfds /path/to/dishes.xlsx /path/to/products.xlsx \
  --rda /path/to/rda.xlsx \
  --output ONEULSIK/Resource/Data/FoodCatalog.sqlite \
  --report Docs/FoodCatalogImport.json
```

RDA 파일에서는 `국가표준식품성분 Database 10.4` 시트와 식품코드 부록을 사용합니다. 원본 형식/열이 달라지면 변환 코드를 먼저 검토해야 합니다. 재생성 중에는 앱을 빌드하지 않고, 완료 후 DB 무결성·검색·앱 빌드를 확인합니다.
