# 대표 음식과 검색 보완

## 데이터

`ONEULSIK/Resource/Data/FoodReferences.json`은 원본 SQLite 위에 놓는 43종의 초기 대표 목록입니다. 대표 음식명, 별칭, 원본 식품코드, 원본 이름, 기준단위, 출처와 기준일을 보관합니다. 영양값은 복사하거나 생성하지 않고 해당 식품코드의 원본 값을 사용합니다. 사용자에게 제시하는 일반 음식 기본값이지 실제 식당 레시피를 검증한 데이터는 아닙니다.

- 밥류, 찌개·국·탕, 김밥·면·분식, 주요 반찬 등을 우선 선정했습니다.
- `순찌·부찌·된찌·김찌·공기밥·공깃밥`, `닭도리탕`, 어순이 다른 참치김밥·크림파스타 등을 포함합니다. 정규화 후 76개 이름으로 연결됩니다.
- 감탄사일 수도 있는 `아아`는 식사 원문에서 미리 치환하지 않습니다. AI가 음식으로 추출했거나 음식 검색창에 직접 입력했을 때만 아메리카노 별칭으로 사용합니다.
- 정확한 일반 조리 음식 이름을 우선 선정했습니다. 기본 순두부찌개는 `순두부찌개 모듬`, 기본 된장국은 `된장국 두부`를 유사 음식 기준으로 사용합니다. 명시한 다른 재료와 브랜드에는 이 기본값을 강제하지 않습니다.
- 동일 이름에서는 무게 기반 자료가 있으면 우선하고, 일반/급식 구분 우선순위, 최신 기준일, 식품코드 순으로 고정했습니다. 최저 열량 여부는 선정 조건이 아닙니다. 추후 더 적절한 원천 자료를 확인하면 참조 코드를 교체해야 합니다.
- 대표 분량은 기존 `FoodPortion`의 출처 있는 정보만 재사용합니다. 없는 분량은 여전히 추정합니다. mL 자료를 g 자료로 간주하지 않습니다. 이 작업으로 43종 전체에 검증된 1인분이 새로 생긴 것은 아닙니다.
- `estimatedPortions`는 검증된 제공량이 아닌 앱의 조절 가능한 기본 추정량입니다. 미소된장국은 인분/그릇당 200g, 고등어구이는 인분/접시당 250g으로 고정합니다. 고등어구이는 기존 일반 고등어구이 분량을 참고하되 석쇠구이 영양값과 연결하므로 분량 근거는 `estimated`, 영양 근거는 `similarFood`로 유지합니다. 미소된장국 200g은 사용자 테스트의 소국 기본값이며 원본 DB가 보증하는 1인분이 아닙니다.
- 기본 추정량은 지정한 원본 레코드와 단위가 일치할 때만 사용합니다. 명시한 g/mL는 우선하며, 반/두 그릇은 각각 0.5/2배로 계산합니다. 다른 브랜드·재료 설명에는 이 기본값을 강제하지 않습니다. 회덮밥도 원본을 고정하되 숟가락 분량은 별도로 추정합니다.
- 로컬 원본 자료만 사용하며 외부 사이트 수집이나 인터넷 검색은 추가하지 않았습니다.

## 연결 규칙

대표 이름이나 등록된 별칭이 정확하게 일치하고, 브랜드·추가 설명이 없으며, 단위가 호환될 때만 지정된 원본 레코드로 바로 연결합니다. 원본 이름·단위·출처·기준일이 목록과 다르면 자동 기본값을 적용하지 않습니다. 소스가 없는 스파게티 같은 중요한 구분은 기존 질문을 유지합니다.

검색은 별칭/띄어쓰기 정규화, 대표 원본명, 재료와 요리 이름의 어순 분리 순으로 후보를 모읍니다. 결과가 전혀 없으면 대표 목록 내 4글자 이상 이름에서 편집거리 1인 후보를 최대 3개 제시합니다. 이 유사 철자 후보는 자동 정답으로 간주하지 않으며 AI 매칭을 거칩니다. 짧은 `김밥`과 `김밤`처럼 다른 단어일 가능성이 큰 이름은 이 방식으로 자동 교정하지 않습니다.

AI가 첫 후보군에서 답을 찾지 못하면 같은 음식의 검색어를 최대 2개 다시 제안합니다. 명시한 브랜드·재료·소스·조리법을 유지하도록 지시하며 앱은 브랜드·g/mL 호환성을 다시 검사합니다. 새 후보를 우선해 한 번 더 판단한 뒤에만 추가 질문이나 기존 영양 추정 경로로 넘어갑니다. 검색을 반복하다 60초 제한을 넘기거나 취소된 요청을 저장하지 않습니다. 모델의 동의어 해석과 유사 음식 판정은 여전히 오류 가능성이 있어 실제 기기 검증이 필요합니다.

## 유지보수

`python3 Scripts/validate_food_references.py`로 전체 참조 코드의 존재, 원본 메타데이터 일치, 일반 조리 음식 여부, 유한·비음수 영양값 및 별칭 충돌을 검증합니다. DB를 교체하거나 별칭을 추가할 때 실행합니다. 영양학적 정확도 검증을 대신하지 않습니다.

원본 DB와 기존 기록은 변경하지 않습니다. 검색 시 일반 음식 중복을 정리하는 기준만 최저 열량 우선에서 참조 코드/자료 우선순위 기준으로 변경합니다.

## 검증 기록

Mac 온디바이스 모델로 아래 5개 문장을 분석했습니다. 첫 실행에서 `절반에`를 놓치는 문제가 발견되어 원문의 분수 표현 뒤 조사 처리를 수정했고, 재실행에서는 모두 추가 질문 없이 기대한 음식 수와 수량으로 연결됐습니다. 앱 빌드 및 JSON 리소스 포함도 확인했습니다. iPhone에서의 모델 응답과 영양값 실측 정확도는 별도 검증이 필요합니다.
