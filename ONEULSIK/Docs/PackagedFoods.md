# 확인된 포장제품

`PackagedFoodReferences.json`은 제품과 규격이 확인된 항목의 **한 포장 전체** 중량·열량·탄수화물·단백질·지방을 함께 저장한다. 식품 카탈로그의 100g 영양값을 덮어쓰지 않는다. 조회 출처 URL과 확인일, 별도 제품 ID를 보존한다.

## 최초 등록

- 오뚜기 콕콕콕 라면볶이 큰컵: 1개 120g, 455kcal, 탄수화물 77g, 단백질 8g, 지방 13g.
- 출처: [코스트코 제품 표시 정보](https://www.costco.co.kr/Foods/Processed-Food/PastaNoodles/Ottogi-Rappoki-Bowl-120g-x-12/p/687105), 2026-11-05 확인. 제조사 직접 확인이 아니라 판매처에 게시된 제품 표시 정보이며, 제품 리뉴얼 시 다시 확인해야 한다.
- 기존 `P108-009000400-0011`의 388kcal/100g은 별도 원본으로 유지한다. 라벨 값에 맞추기 위해 열량만 교체하거나 같은 비율로 탄단지를 만들어내지 않는다.

## AI 식사 기록 흐름

1. 일반 음식명은 브랜드 없는 조리 음식·식재료 후보에서 먼저 찾는다. 포장제품 이름이 정확히 일치하더라도 일반 음식 후보를 밀어내지 않으며, 검색어를 바꿔 재검색할 때도 제품 후보는 분리한다. 브랜드·제품 고유명이나 봉/팩 등 포장 단위가 명시된 경우에만 제품 경로를 우선한다. 포장 단위만으로 특정 브랜드를 확정하지 않는다.
2. 제품명과 120g 규격을 사용자에게 보여주고 확인을 받는다. 정확한 이름을 입력해도 현재는 규격 확인을 거친다. 다른 제품이면 상단 입력을 수정하여 다시 분석한다.
   제품 선택은 전체 너비 카드로 표시하며, 제품명과 브랜드·용량·열량을 별도 줄로 나눈다. 다른 질문도 선택지가 하나면 전체 너비를 사용하고, 짧은 복수 선택지는 기존 2열을 유지한다.
3. 확인 후 제품 한 개의 영양정보에 개수를 곱한다. 반 개는 227.5kcal, 두 개는 910kcal다. 명시적인 조리 전 60g은 반 개로 계산한다.
4. 조리 후/불린/끓인 무게 또는 맞지 않는 단위는 포장 개수를 다시 묻는다. 물이 늘어난 무게에 건조 제품의 영양 밀도를 곱하지 않는다.
5. 이전 음식과 아직 처리하지 않은 음식은 유지한다. 저장에는 제품 ID, 제품명, 포장 중량, 라벨 영양값, 출처 및 확인일이 남는다.

수량 없이 입력한 가공식품(예: 제품 이름만 입력)은 인분으로 보지 않고 1개(DB 제품 총중량 `package_amount`)로 가정하며, 카드에 "수량이 없어서 1개로 가정했어요"를 붙인다(2026-11-17 결정). 이 안내는 기록에 저장하지 않는다. 총중량 정보가 없으면 1개 중량을 묻고, 한 줄이 1,000kcal를 넘으면 양 확인 질문을 거친다.

검증된 규격이 없는 DB 가공식품은 AI 분량 추정으로 넘어가지 않는다. 명시적인 g/mL는 DB의 같은 단위 기준으로 계산할 수 있지만, 조리 상태와 제품 규격은 별도 확인이 필요하다. 일반 음식에는 기존 대표 분량/추정 흐름을 유지한다.

일반 음식 후보를 찾지 못했지만 관련 제품 후보가 있으면 제품 확인 카드를 표시한다. 브랜드가 있는 입력은 해당 브랜드의 후보만 사용하며, 찾지 못했다고 다른 브랜드나 일반 음식의 추정값으로 대체하지 않는다. DB 가공식품도 확인 없이 자동 기록하지 않는다. 제품 확인 카드의 `100g 기준`은 **한 포장 용량이 아니다**. 확인된 포장정보가 있는 항목만 `1개 120g`처럼 표시하고, 제품 확인 후에도 확인되지 않은 포장 용량을 임의로 추정하지 않는다.

`aliases`는 제품을 제안할 수 있는 검색 별칭이고 `productAliases`는 제품임이 명확한 별칭이다. 예를 들어 `라면볶이`는 일반 음식 검색을 먼저 거치지만 `콕콕콕 라면볶이`는 제품 확인으로 바로 진행한다. 일반 음식 후보가 없으면 `라면볶이`에도 기존의 검증된 제품을 제안할 수 있다. 특정 음식별 예외보다 공통 후보 분리 정책을 우선한다.

2026-11-06 모의 모델/카탈로그 검증: 정확히 일치하는 가공식품보다 조리 음식 변형명 우선, 재검색 중 제품 혼입 차단, 제품만 있는 경우 확인, `만두 한봉지`의 브랜드 미확정, 명시 브랜드 필터, 제품 확인 후 브랜드·수량 보존, 일반 계란빵 참고값의 포장 입력 제외를 통과했다. 실제 DB와 모의 모델을 사용하는 기존 컵라면·계란빵·국자 분량 회귀 점검 및 iOS 시뮬레이터 빌드도 통과했다. `참치김치김밥`은 포장제품 대신 일반 음식 `김밥 참치 김치` 후보로 전달되는 것을 확인했다. 이는 후보 경로 검증이며 해당 원본의 단위·영양값이나 온디바이스 모델 자체의 해석 정확도를 보장하는 검증은 아니다.

직접 검색 화면은 기존 DB 영양값을 유지한다. 이 제품 확인 기능은 현재 **AI 식사 기록**에 적용되며 모든 가공식품의 포장정보를 확보한 것은 아니다. 기존 저장 기록도 소급 변경하지 않는다.

## 의심 항목 격리

`FoodCatalogQuality`는 계란빵 `D402-077000000-0001`, `D702-077000000-0001`을 검색과 ID 조회, AI 후보 및 선택에서 제외한다. 두 항목은 100mL당 158kcal로 저장되어 있으나 원본 단위를 재확인하지 못했다. g으로 강제 변경하지 않고 SQLite 원본은 보존한다. 다른 브랜드의 계란빵을 같은 음식이라고 확정하지 않는다.

브랜드와 추가 설명이 없는 `계란빵`/`달걀빵`은 `PreparedFoodReference`의 일반 음식 참고값을 사용한다. 단위 생략 또는 인분은 기본 1개로 제안하며 반 개·2개·직접 입력한 g은 보존한다. 명확한 단일 음식명과 수량은 추출 모델도 거치지 않는다. 이 경로는 영양·분량 추정 모델의 응답 성공 여부와 무관하게 처리하며 재료를 되묻지 않는다. 브랜드나 콘치즈 같은 추가 재료가 명시된 음식에는 이 기본값을 자동 적용하지 않는다.

2026-11-05 확인한 [FatSecret 계란빵 검색 결과](https://www.fatsecret.kr/칼로리-영양소/search?frc=True&q=계란빵)의 일반 계란빵은 1개 126kcal, 탄수화물 10.66g, 단백질 6.16g, 지방 6.32g이다. 함께 표시된 100g당 157kcal와 개당 열량의 비율로 약 80g을 환산했다. **80g은 직접 확인한 제공 중량이 아니며 반올림된 열량으로부터 구한 근사값이다.** 직접 입력한 g도 이 근사 중량으로 비례 환산한다. 식약처 원본이나 특정 제품의 라벨 값이 아니므로 별도 ID·출처·확인일로 보존하고 `.estimated`로 기록한다. 실제 조리법과 크기에 따른 차이가 있으며 기존 공공 DB를 덮어쓰지 않는다.

모의 모델과 실제 DB를 이용해 기본 1개·반 개·2개·60g, 앞서 확인한 라면볶이 및 뒤의 참치김치김밥 유지, 제품명/보조 정보 분리를 검증한다. 실제 온디바이스 추정값과 UI의 최종 외관은 실기기에서 추가 확인한다.

## 추가 등록 기준

- 제품명·제조사/브랜드·규격이 일치하는 제품 표시 자료를 확보한다.
- 중량과 4개 영양값 모두 같은 포장 기준인지 확인한다.
- `aliases`는 정확한 이름만 등록하고 맛/용량 변형을 묶지 않는다.
- 기존 DB ID와 연결하는 경우 제조사·이름도 함께 검증한다.
- 출처 및 확인일을 기록하고 개수/반 개/g 입력/브랜드 불일치 회귀 점검을 실행한다.

## 비현실적인 총중량(2026-11-23, #37)

제품 1개 총중량이 1,500g(또는 1,500mL)을 넘거나 1개 열량이 1,500kcal를 넘으면 총중량을 1회 먹은 양으로 쓰지 않고, 일반 음식과 같은 분량 흐름으로 보냅니다(`AIMealEntryService.packageAmountLimit`, `packageCalorieLimit`). 순서는 대표 분량표에서 입력 이름으로 찾은 분량 → AI 분량 추정 → "‘음식’을 얼마나 드셨나요?" 선택지 질문이고, 영양값은 고른 제품의 100g(mL)당 값을 씁니다. 방문자에게 무게(g·mL)는 묻지 않습니다. 전시 대비 점검에서 업소용·여러 개 묶음 포장(예: 초코케이크 6,000g 27,660kcal, 핫초코 분말 2,000g 8,500kcal)이 1개로 기록되던 문제 때문입니다. 제품 확인 질문의 선택지 설명(총중량·열량)도 같은 기준을 따르고, 넘으면 100g(mL) 기준 값만 보여줍니다. 사용자가 g/mL를 직접 적은 입력과 1,000kcal 양 확인 질문은 그대로입니다.
