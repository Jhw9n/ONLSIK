# Claude 작업 안내

문서 경로는 이 파일이 있는 앱 폴더 기준이다. Git 저장소 루트는 한 단계 위일 수 있으므로,
저장소 루트에서 작업할 때는 앞에 `ONEULSIK/`를 붙인다(예: `ONEULSIK/Docs/GitWorkflow.md`).

이 프로젝트에서 GitHub 이슈, 브랜치, 커밋, 푸시, PR을 다룰 때는 먼저
`Docs/GitWorkflow.md`(저장소 루트 기준 `ONEULSIK/Docs/GitWorkflow.md`)를 읽고 따른다.

테스트·데이터 파일·음식 DB 작업 때는 먼저 `Docs/TestingWorkflow.md`
(저장소 루트 기준 `ONEULSIK/Docs/TestingWorkflow.md`)를 읽고 따른다.

## 기본 원칙

- 사용자와 한국어로 소통하고, 이슈·커밋·PR 본문도 한국어로 작성한다.
- 작업 전에 현재 브랜치와 변경 사항을 확인하고 사용자의 기존 변경을 보존한다.
- Git 저장소 루트는 `git rev-parse --show-toplevel`로 확인한다. 앱 폴더와 저장소 루트가 다를 수 있다.
- 사용자가 전체 흐름을 명시적으로 맡기면 기존 이슈 확인부터 이슈 생성, 브랜치 생성,
  구현·검증, 커밋, 푸시, 초안 PR 생성까지 진행할 수 있다.
- 일반적인 구현 요청만으로 커밋·푸시·PR 생성까지 허가받았다고 해석하지 않는다.
- 실제 GitHub 작업에는 연결된 계정 또는 GitHub CLI 인증과 필요한 실행 권한이 있어야 한다.
  권한이 없으면 중단 지점을 알리고 요청하며, 완료했다고 보고하지 않는다.
- PR 머지, 강제 푸시, 원격 브랜치 삭제, 파괴적인 Git 명령은 별도 요청 없이 실행하지 않는다.
- 이 안내 파일을 만들거나 읽었다는 이유만으로 이슈·브랜치·PR을 생성하지 않는다.
